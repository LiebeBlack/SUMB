Características

Todo lo que un inspector USB necesita

Diseñado con Clean Architecture y pensado para funcionar siempre: si un componente falla, el siguiente toma el relevo.

📡
NÚCLEO

Hotplug en tiempo real

Suscripción WMI a __InstanceOperationEvent sobre Win32_PnPEntity con respaldo automático a polling (1.5 s) si el evento se rompe.

🔍
NÚCLEO

Parsing VID / PID

Extracción con regex de VID_xxxx y PID_yyyy desde USB\VID_045E&PID_0779\…, case-insensitive y con fallback por segmentos.

🧵
NÚCLEO

Thread-safe por diseño

Cada hilo WMI aísla COM con CoInitializeEx/CoUninitialize y todo cambio de UI se despacha al hilo principal de WinUI 3.

⚙️
BETA

Inspector de kernel

Driver KMDF que captura URBs e IRPs en ring 0 mediante IOCTLs con ring buffer protegido. Se activa con un ToggleSwitch en Ajustes.

🔌
TIER 2

Captura WinUSB nativa

Sin driver: lee pipes bulk/interrupt con winusb.sys y SetupAPI puro (ctypes), sin dependencias externas.

🛡️
RESILIENCIA

Degradación automática

Cascada Kernel → WinUSB → WMI. La aplicación nunca colapsa: cada nivel cierra sus recursos y notifica el motivo del fallback.

Motor híbrido

Tres niveles, una sola telemetría

Máxima capacidad primero. El TierManager decide en cascada y el usuario siempre ve un estado claro en Ajustes.

TIER 1

Kernel KMDF dinámico

Máxima capacidad · Ring 0
  • Driver cargado bajo demanda, sin persistencia en boot
  • Captura de URBs (Submit URB) e IRPs en tiempo real
  • IOCTLs METHOD_BUFFERED + ring buffer con spinlock
  • Elevación UAC única al activar; DeleteService al salir
TIER 2

WinUSB user-space

Alta capacidad · Ring 3
  • API nativa winusb.sys sin drivers extra
  • Enumeración con SetupAPI puro (ctypes)
  • Lectura de pipes bulk/interrupt en hilo daemon
  • Funciona si el Test-Signing está deshabilitado
TIER 3

Estándar · WMI

Operativa total · Sin privilegios
  • Consulta Win32_PnPEntity por WQL
  • Hotplug por __InstanceOperationEvent + polling
  • Identificación VID/PID y estados de dispositivos
  • Nunca falla: la app siempre queda funcional
T1 Kernel → T2 WinUSB → T3 WMI  ·  siempre al mejor nivel disponible
Modo Avanzado (Beta)

El driver que no toca tu sistema

Un filtro KMDF minimalista, sin persistencia, sin BSOD por diseño y con limpieza total al cerrar.

📦

Carga dinámica

El .sys se copia a %TEMP%\BusLens\, se registra con CreateServiceW (demand-start) y se inicia con StartServiceW. Cero claves en boot.

🔐

Seguridad en ring 0

Adjunto solo bajo demanda (IOCTL_ATTACH), passthrough con completion, __try/__except en la lectura de URBs y spinlock en el ring buffer.

🧹

Purge garantizado

Al desactivar o cerrar: ControlService(STOP) + DeleteService + borrado del archivo temporal. No quedan recursos colgados en el kernel.

💡
Test-Signing: si el kernel rechaza la imagen (ERROR_INVALID_IMAGE_HASH), BusLens degrada automáticamente a WinUSB o WMI. Para usar el driver, compílalo con el WDK y habilita bcdedit /set testsigning on (o firma el binario).

Puesta en marcha

Instalación y uso

Tres formas de ejecutar BusLens: desde el código fuente, como ejecutable único o con el instalador.

🐍

Desde el código

# Windows 10/11 · Python 3.11+ x64
pip install -r requirements.txt
python run.py
📦

Ejecutable único

# Compilar con PyInstaller
python build_exe.py --clean
# Resultado: dist\BusLens.exe
🖥️

Instalador

# Con Inno Setup 6 instalado
ISCC installer\buslens_setup.iss
# Resultado: BusLens_Setup_v1.0.0.exe
🛡️
Sin PyWinRT: si la máquina no tiene la proyección WinUI 3, la aplicación sale con un mensaje claro (código 1) en lugar de un traceback. En Windows con pip install -r requirements.txt todo funciona.
